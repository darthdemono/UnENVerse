## The bugs that mattered

Listed because each was silent - nothing surfaced them at runtime.

1. **`escAttr` did not escape `&`** (`utils.ts`). A secret containing `&amp;` was
   HTML-decoded on read-back, so **copy-to-clipboard returned the wrong secret**.
   Worst bug in the codebase.
2. **Two disagreeing entry identities.** `save_vault` keyed on
   `provider|account_name`, the RBAC merge on `provider|account_name|key_id`.
   Version history and audit rows could land on the wrong entry. Unified on a
   stable `id`, backfilled on load.
3. **Master password stored as a sub-user hash.** The desktop seeded an `admin`
   row whose `password_hash` _was the master password_, turning the sub-user
   login into an oracle for the vault key. Removed.
4. **Username enumeration oracle.** `verify_user_password` returned `Err` for a
   passwordless user (→ 500) but `Ok(None)` for a nonexistent one (→ 401), and
   only the 401 path incremented the rate limiter. Unthrottled. Both are
   ordinary credential failures now.
5. **"Lock" did not lock.** `DELETE /api/unlock` dropped only the caller's
   session while every user session held its _own copy_ of the vault key. Owner
   lock is now global.
6. **Sessions never expired.** A leaked token was valid until process restart.
   Now an idle TTL (`--session-ttl-mins`, default 480) that every authenticated
   request slides - which is what finally made `/api/ping` mean anything.
7. **Keep-alive never worked.** It read a `_token` field that does not exist (the
   field is `token`), so every ping went out as `Bearer ` and was rejected.
8. **Settings save disconnected your remote vault.** `saveSettings()` called
   `applyRemoteConfig()`, which reassigned `st.store` from an unchecked toggle.
   Opening and closing Settings while connected silently dropped you to local.
9. **The `chunk` secret type could never be saved.** It was in the dropdown, but
   `dynamicSecretFields` hid its key input while `saveModal` still required
   `api_key`. Removed; existing entries relabel to `env_var`.
10. **Lost-update window** (see Pass 3.1 below).

Also: remote status checks used bare `fetch()` and reported "Unreachable" for any
self-signed HTTPS server; expand/reveal state was array-index-keyed so it jumped
cards after deletes; lock-on-hide fired on every alt-tab; cron month names were
off by one and `nextFireTimes` could not see past ~7 days; `Exporter.yaml` emitted
invalid YAML for quoted values; card rendering was O(n²).

## Pass 3.1 - the lost-update fix (most recent work)

Opening to LAN made the desktop and its peers concurrent writers on one database.
The desktop wrote the whole blob unconditionally, so a peer's edit landing between
the desktop's load and its next save vanished silently.

The check now lives **inside `save_vault`**, in the same `BEGIN IMMEDIATE`
transaction as the write:

```rust
pub struct SaveCtx<'a> {
    pub actor: Option<&'a str>,
    pub expect_version: Option<&'a str>,   // None = unconditional
}
```

Placement is the whole point. A caller that reads, compares, then writes has a
race between the compare and the write - which is what the server's `If-Match`
handling was. A caller that forgets is silently unprotected - which is what the
desktop was.

Three things surfaced while doing it:

- **Audit rows were written outside the transaction**, so a rejected write still
  logged changes that never happened. Now inside; test asserts no trace.
- **The GET ETag and the CAS value could disagree.** The ETag re-hashed parsed
  JSON; the CAS compares the stored `data_hash`. They match today only because
  `serde_json::Value` iterates sorted. The ETag now reads the stored value.
- **Read ordering is load-bearing.** Version-then-data can only pin an _older_
  version, which fails the CAS and retries. Data-then-version passes the check
  while merging a stale base - the clobber itself. Commented at the site.

## What Worked

- **Mechanical id auditing.** Before/after diffing every `id="..."` against
  `git show HEAD:index.html`, cross-checked against every `getElementById`,
  caught what types and builds cannot. Used for the `index.html` split and the
  crossed-DOM-id rename. Reuse this for any markup move.
- **Verbatim extraction over retyping.** Both large splits (`chunk-ops.ts` →
  `chunks/`, tool panes → `tools-markup.ts`) used `sed` line ranges, so no
  transcription errors were possible. The compiler then found the four missing
  imports.
- **Letting tests correct the plan.** Three RBAC tests failed on first run and
  _the tests were wrong, not the code_ - `entry_write_allowed` genuinely required
  every declared scope. That surfaced the usability problem that led to the
  ANY-match relaxation.
- **Structs over positional `Option<&str>`.** `SaveCtx` exists because swapping
  actor and version would compile and pass every test.
- **Asking before implementing.** The user's "clear all confusions first"
  instruction avoided building the wrong permission model twice.

## What Didn't Work

- **`rm -rf .claude/worktrees` was blocked by the sandbox classifier.** Not
  worked around. **Still pending - see Next Steps.**
- **`*/n` inside a JSDoc block** closed the comment early and produced ~30
  bogus TS errors. Rephrase step syntax in prose inside doc comments.
- **Migration ordering, caught before it ran.** The row→expression migration was
  initially placed _before_ class seeding, which on a fresh vault would have left
  the built-in Admin/Moderator/Viewer classes with no rules - silently denying
  everything. Now after seeding, with a test.
- **Read ordering in the merge path**, first version had it backwards (above).
