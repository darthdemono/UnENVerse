Your AI agents need credentials. They do not need your vault.

UnENVerse holds the credentials, 2FA seeds, configurations and recovery material for the services, scripts and coding agents you run. One vault, many jobs

Give agents a boundary

An AI agent can use one credential through unv exec. The value goes into its child process. Routine output stays redacted.

Keep the old mess useful

Import .env files, Bitwarden, 1Password and Proton Pass exports, a Nextcloud config.php, and plain-text Ente Auth, Aegis, 2FAS, andOTP or Google Authenticator exports. The report names every item that did not make it. Encrypted exports are refused by product name.

Generate what the stack expects

WireGuard, Docker Compose, nginx, Kubernetes, Traefik and HAProxy use the same vault records. A config checker finds mistakes before a node gets a file.

See it working

One workflow, end to end

Rotating one credential that several configs share:

  1. Edit the entry once. Every config that references it, such as an .env file, a WireGuard interface or an nginx block, renders from the new value. Compose files keep ${VAR} for Compose itself to fill in.
  2. Read the diff. Config history shows each file's before and after, with the secret masked.
  3. See what to touch. The blast-radius report names the machines that held the old value.
  4. Apply on purpose. A node agent on each host can observe a file, and, if you allow it, receive the new one, with an optional human approval bound to the exact bytes.

Shipped parts: references and rendering, config history, blast radius, node agents with approval. Node agents install on Linux (systemd).

Honest limits

  • It is not a hosted service. You run it and you back it up.
  • A forgotten master password cannot be recovered. Keep the .vaultbak backup and the vault.salt file safe.
  • It is not a browser autofill extension.
  • macOS builds are not published yet.
  • The node agent is documented for Linux with systemd.

Why you can check it

  • Apache-2.0, source on GitHub.
  • Every release asset carries a keyless Sigstore signature and a checksum.
  • A security page that says what is protected and what is not, and a reporting route.
  • No account and no analytics in the app.
