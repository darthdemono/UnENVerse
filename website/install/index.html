Install

Three things can be installed, and they share one vault format: the desktop app, the unv command line, and unv-server for a vault several people or machines reach. Current release: {{VERSION}}.

Desktop app and command line

Get the file for your system from the download page. Every file has a SHA-256 sum and a Sigstore signature.

# Debian or Ubuntu (amd64 or arm64)
sudo apt install ./UnENVerse_{{VERSION}}_amd64.deb

# Fedora or RHEL
sudo dnf install ./UnENVerse-{{VERSION}}-1.x86_64.rpm

# Any Linux: the AppImage
chmod +x UnENVerse_{{VERSION}}_amd64.AppImage && ./UnENVerse_{{VERSION}}_amd64.AppImage

# Command line only (add -musl for a static build that runs on Alpine)
tar xzf unv-{{VERSION}}-linux-x86_64.tar.gz && ./unv --version

On Windows run the -setup.exe (x64 or Arm), or unpack the .zip for the command line. macOS is built and tested in CI but not released, because nothing could be signed or notarized without an Apple Developer account. See platforms.

Server in Docker

docker run -d -p 127.0.0.1:8743:8743 -v unv-data:/data -e UNV_PASSWORD=... \
  ghcr.io/darthdemono/unenverse/unv-server:latest

The image is published for linux/amd64 and linux/arm64. The port is bound to this machine only: the server speaks plain HTTP unless started with --tls, and the master password travels in every sign-in. Add --tls, or put a TLS proxy in front, before reaching it from other machines.

Verify, update, uninstall

  • Check the SHA-256 of the file against SHA256SUMS on the release before running it.
  • unv update check reports a newer release; unv update install installs one whose signature verifies.
  • Uninstalling the app does not delete your vault (vault.db and vault.salt in the io.unenverse data folder). Back it up first with unv backup export; a forgotten master password cannot be recovered.
